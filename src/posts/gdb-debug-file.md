这几天刚去学习了一下用 gdb 调试代码，在这儿记下来。

首先，编译代码的时候需要加上 `-g` 选项，说明要加上调试信息，这样才可以正常调试。例如：

```ansi
[1;94m$[0m g++ -g oi.cpp -o oi.exe
```

随后，即可使用 gdb 打开文件进行调试。直接使用 `gdb [file name]` 即可。

```ansi
[1;94m$[0m gdb oi
[0;1;35mGNU gdb (GDB) 7.8.1
[0mCopyright (C) 2014 Free Software Foundation, Inc.
[0mLicense GPLv3+: GNU GPL version 3 or later <[0;32mhttp://gnu.org/licenses/gpl.html[0m>

[0;1;94m(gdb)[0m  [0;3;32m# 现在可以键入调试命令了[0m
```

### info source

可以简写为 `i source`
获取代码信息，可以查看 gdb 获取的代码路径是否正确。

例如：
```ansi
[1;94m(gdb)[0m info source
Current source file is oi.cpp
Compilation directory is D:\MyCode
Located in D:\MyCode\oi.cpp
Contains 65 lines.
Source language is c++.
Compiled with DWARF 2 debugging format.
Does not include preprocessor macro info.
```

### file

参数是文件路径，可以重新打开一个文件调试。  
例如：

```ansi
[1;94m(gdb)[0m file D:\MyCode\oi
[0mReading symbols from [032moi[0m...done.
```

### cd

同任何命令行的 cd 命令一样，切换工作文件夹。

## 程序运行时

`run` 命令。
命令缩写是 `r`。  
**运行程序**，直至遇到断点或程序结束。

`print` 命令。
命令缩写是 `p`。
在**程序运行**时输出变量（数组）的值。

`break` 命令。  
命令缩写是 `b`，参数是行号或函数名。  
表示在函数或第几行设置断点。  
例如：

```ansi
[1;94m(gdb)[0m break main
Breakpoint 1 at [0;34m0x40153d[0m: file [0;32moi.cpp[0m, line [0;2m9[0m.
[1;94m(gdb)[0m b 43
Breakpoint 2 at [0;34m0x401722[0m: file [0;32moi.cpp[0m, line [0;2m43[0m.
```

`continue` 命令。
命令缩写是 `c`。
遇到断点后使用，**继续执行**，运行到下一个断点或程序结束。

`delete` 命令。
命令缩写是 `d`。
删除断点，参数是**断点编号**。就是 `Breakpoint 1 at []: file [], line [].` Breakpoint 后面的数字。

`next` 命令。
命令缩写是 `n`。
执行当前行语句，如果当前行有函数调用，则将其视为一个整体执行。

## 获取信息

`info breakpoint`  
可以简写为 `i b`，查看断点信息。

`info registers`  
可以简写为 `i reg`，查看寄存器信息。
